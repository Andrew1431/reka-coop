## Issues
1. (Fixed, verified locally: the host switches on a talk a guest asks for when only the guest's state shows it; also fixed the wheel's collider shoving the carrier and the empty carry after hand-in) Lost wheel: while the guest held the wheel, the guest couldn't talk to the merchant to hand it in. Workaround: guest dropped it, host picked it up and talked. Likely: the hand-in talk (`Dialogue_FoundWheel`, a GenericPOICondition fed by the carry) is switched on by the carrier's own game, but ActiveSync makes the guest follow the host's on/off state, and on the host nobody local carries the wheel, so it stays off on the guest. Same family: story objects driven by the local player's state.
2. (Open) Tomek: the guest's first conversation worked, then the guest couldn't talk to him again until the host talked to him once; after that the guest could. Likely: something the first talk switches on or off (talkable state, next dialogue node) changes on the guest's copy but not the host's, or the reverse, until a host talk refreshes it. Look at what the host's talk changes (ActiveSync/Places log lines) versus the guest's.
3. (Built, to test: PopupSync, the conversation's leader chooses, others watch) Story choice after the raven man's (debt collector's) talk: a split-screen decision ("I'll see what I can do." / "Better pay your debts in future!") shows on the host and isn't synced to the guest. The mod has nothing for it yet: no hook on `POI_Decision` (research/npcs-quests.md: rumors can carry `decisionToTriggerOnLastLineOfDialogue (POI_Decision)`). Probably wants the same treatment as conversations: the starter chooses, the others see the same screen and highlight, read-only, and the result runs once on the host.
4. (Built, to test: PopupSync, loot boxes shown on every copy) Quest rewards: when one is granted, the reward popup only shows on one screen (the items themselves arrive through the shared pack). Guests skip their own `GiveTrialReward` / quest `POI_Loot` so nothing is given twice, which also skips the popup. Fix: the host sends "reward shown" with the loot list, and others show the game's reward popup without granting anything.
5. (Fixed, verified locally both ways: the dropper streams the pose until it rests) Pumpkin quest: carrying pumpkins to the farm works. But a dropped pumpkin freezes in mid-air on the other player's screen, and only sometimes ends up in the right place later. On the dropper's own screen it rolls away normally. Likely: CarrySync holds the remote copy still while it's carried (kinematic / no physics) and on Drop only places it at the carrier's spot, so the other copy either stays frozen or runs its own physics apart from the dropper's. Fix: after a drop, the dropper streams the object's pose until it comes to rest, and the others follow it (kinematic), then hand it back to physics at the final spot.
6. (Fixed, verified locally: her talk starts from her AI via DialogueFunctions.StartDefaultDialogue, now sent to the host; player detectors run on the host for everyone) The guest walking up to the old woman (Baba Jaga) started her conversation, but the host, far away, was not moved there. The gather has no distance limit. The logs show the mod never saw this talk at all: no "starts"/"led by" line on either copy after Dunja's. So this talk starts through a path DialogueSync doesn't hook (a cutscene, Baba Jaga's own dialogue manager, or a trigger that runs dialogue directly). Next: find what starts it (trigger near her hut, `TasksTracker.bjDialogueManager`, `trialIntroDialogue` = MapIntroDialogue) and route it through the same leader/gather path.
7. (Built, to test: gate close/open synced, others moved in beside the closer) Baba Jaga's gate: it opens, and when a player walks in it closes behind them, but only on that player's own screen; the other player can still walk in. That's harmless now, but the user would prefer it in sync, with the other player brought inside too. Next: find the trigger and animator that close it (likely a PlayerDetection or trigger inside the yard, tied to issue 6's talk). When it fires on anyone, close it for everyone and move the others inside, the same way the dialogue gather does. If the other player is already inside when it closes, do nothing.
8. (Built in 0.3.14, to test) Collect 10 mushrooms: the shared pack has 20 on both copies, but the host's task reads 1/10 while the guest's is checked. The task doesn't count the pack. It counts the player's own pickup stats (`StatsTracker.collectiblesCollected[Item]`), which are per player: host `collectiblesCollectedTotal=7`, guest 19. Since the host owns trials, only the host's own pickups count, and the 0.3.13 self-repair keeps unticking the guest. Same for honeycombs and likely other "collect N" tasks. Fix: when the host receives a guest's pickup (WorldObject Collected), also add it to the host's `StatsTracker` (collectiblesCollected for that item + the total) so the host's task counts everyone's pickups. Check the craft, POI and people-helped stats the same way.
9. (Fixed, verified locally: the guest's talisman unlock and stat reach the host) The guest took the talisman and got the mortar-and-pestle skill; the host didn't. desync.log shows the guest's task "find the talisman" (T0.2) checked, then put back to the host's unchecked by the 0.3.13 self-repair. The saved progress (`TutorialManager_v2`, `PoiMapHistoryTracker`) also differs every round. Cause, shared with 8: all story state flows one way, host → guest. When the guest does a story action itself (picks up the talisman, solves a place, unlocks a tool, ticks a task), it happens only on the guest. The host never learns of it, and the repair then reverts the guest. Only conversations are forwarded so far (the guest's start runs on the host). Fix direction, in order:
   - Forward the guest's story actions to the host to run there, the way conversations are: the talisman/POI pickup that grants the item and unlock, POI solves, tool unlocks (`UseItemManager.UnlockItem`). The host's normal state sync then brings everything back to the guest.
   - Or, as a catch-all: the guest reports "gained" progress (unlock, task done, step done, story flag set) and the host adopts it if it only adds progress. The self-repair must then stop reverting gains the host hasn't adopted yet, only things the host has but the guest lacks.
   - Until then, the self-repair makes guest-driven progress look worse, so consider limiting it to the guest *missing* the host's progress.
10. (Fixed, verified locally) Lutki: picking up the planks with two players never made the Lutki stand. Each loose plank sets its own place condition when picked up (dev condition log: host had planks 01 and 03, guest 02 and 04), so neither copy had all four. ConditionSync now sends every GenericPOICondition set to all copies.
11. (Fixed, verified locally) "So you must be the Lutki..." (Reka's monologue) showed only on the host, even when the guest walked up: guest-started dialogue runs on the host, and passive lines weren't sent. They are now shown on every copy.
