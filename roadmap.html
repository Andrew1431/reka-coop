Baba Jaga's apprentice, now with company

Reka Co-op Roadmap

A BepInEx 6 mod that lets 2–4 friends share one Reka world: walk the same forest, ride the same chicken-legged hut, build, brew and take quests together. The host's save is the world. Guests are avatars that send requests to the host.

What we found

No netcode, but Steam is wired in

The game ships no Mirror, Netcode, FishNet or Photon. It does bundle Facepunch.Steamworks, including SteamMatchmaking and SteamNetworkingSockets, and calls SteamClient under Reka's real app ID. Lobbies and P2P are available without adding a DLL. The lobby methods survived IL2CPP stripping: creating a lobby, its data and rich presence all work.

Readable, unobfuscated code

About 5,100 types in Assembly-CSharp, with descriptive names in the global namespace. Only Rewired, which the vendor obfuscates, is scrambled. Metadata v31 is unencrypted. This is the same Il2CppInterop path as Big Walk.

Saves are folders of XML

%AppData%\RekaGame\Saves\<slot>\ holds Meta, House, Inventory, Character, Progress, PoiHistory, FogMap, HeightMap and more. Joining a game can work by sending the host's save folder, loading it with the game's own loader, then streaming changes.

Procedural world, combat-free

EnvironmentGenManager, MapLoader and chapter generation settings are present, and HealthBar is the only combat-related type. We don't have to sync any combat. The hard parts are world generation, the hut and story state.

Built-in debug panels

Dozens of Debug*Section and Marketing*Tab registrations (teleport, cheats). They're ready-made hooks for test bots and repro setups.

Greenfield

There are no Reka mods on GitHub, Nexus or Thunderstore, no Thunderstore community, and no Workshop. The developer has not said anything about co-op. 1.0 launched today, so expect patches that break hooks.

  2. Research & static survey

    donephase 1

    Mapped assemblies, Steam integration, save format and subsystem classes from the metadata strings. Checked the tooling state and prior co-op mods.

  3. Workspace

    donephase 2
    • Done: two hardlinked test copies (host, client). The Steam install is untouched, and the game had no single-instance flag to remove.
    • Done: BepInEx be.791 IL2CPP installed, pinned by SHA-256 bb1c5109…b3ec6f9a, and the interop assemblies generated.
    • Done: both copies ran at the same time on one Steam account, each started Steam successfully and reached the main menu, each with its own Unity log.
    • Done: the plugin project with build, launch and stop scripts. Each copy keeps its saves in its own folder through the game's built-in save-folder override, and each has its own logs.
    • Done: the networking layer (LiteNetLib). The host and client copies connect over loopback, handshake, and show the round-trip time on screen.
    • Done: both copies load the same save automatically, sit side by side in windows titled HOST and CLIENT, and save screenshots on request.

    Memory is tight but three copies fit: a third joined a running two-player session for the late-join test.

    Exit: a plugin logs every frame in two copies running at once, and the real save is unchanged by hash.

  4. Hook map

    donephase 3

    Seven parallel research passes mapped every remaining slice from the interop signatures and save files, each with a sync design and a first step (research/*.md). Each hook is proven by a log line when its slice is built.

    • Steam: lobbies, invites, rich presence and P2P all survive in the build. Lobbies go through the game's Facepunch; traffic goes through the flat ISteamNetworkingMessages exports.
    • World: no single seed, but a per-step generation state exists. Join sends the host's whole save (about 90 KB gzipped so far). WeatherManager has a ready-made snapshot API.
    • Hut: ChickenLegsBehaviour + ChickenLegsAIController. Riders are carried by PlayerPlatformCarry, not parented. No test save has the hut unlocked yet.
    • Building: BB_Building and the game's own compact HouseBlockSpec; placementIndex is the network id. HouseBuildRegistry turned out to be unrelated.
    • Inventory: two 20-slot grids, an overflow list and money, changed through one message bus. Pickups have ids that match across machines on the same save.
    • Story: custom dialogue (rumours, decisions, one dialogue box, a camera takeover), chapters in TasksTracker, flags in string-keyed static tables.
    • Gear: tools and backpack follow bones through ObjectFollower; equip state on UseItemManager; footsteps via an animation event.

  5. See each other

    doneplayers

    Working: the remote player appears as a puppet copied from the local body with only its meshes, bones and animator kept. It walks and animates from 15 Hz snapshots shown 100 ms behind. A test bot walking in the client copy shows up in the host copy.

    • Done: each player's own appearance. It comes from a co-op profile kept outside any save, imported from your newest save the first time and sent on join and whenever it changes. The host replays everyone's look to players who join later.
    • Done: backpack, lantern and held items on the other player, plus their footstep sounds.
    • Done: a guest who has never played gets a random look of their own instead of turning into the host's twin. Still to do: a real character-creator step for them.
    • Done: a name tag over each player (their Steam name).
    • To do: an automated distance check for the exit test.

    Exit: a bot walks a circle on the client and the host sees it within tolerance, over loopback.

  6. Same world, same day

    donejoin

    Send the host's save folder as a snapshot, load it on the client in a sandboxed slot, then sync time of day, weather and wind. Joining mid-game replays the current state.

    • Done: a third copy joined a running session and got the house, story, trials, containers, places and hut pieces. Then all three ran 150 random builds and removals each at once, and the houses matched.
    • Done: the third player quit and rejoined. Their inventory came back intact, and their old figure disappeared from the other two screens.

    Exit (met): a late-joining third client produces the same state hash as the host.

  7. Ride the hut

    in progresshut

    The host owns the one hut. Each guest's copy becomes a mirror: its AI and root motion are blocked and host data drives it. Riders send their position relative to the hut floor. Guests can ask the host to call the hut. Needs a test save past the hut ritual.

    • Done: a guest at the controls steers the host's hut. The guest's own input goes to the host 20 times a second, and the host's camera and controls are left alone. Letting go leaves the hut standing where it was steered.
    • Done: a guest rode the hut for 116 m and stayed put on the floor. Backport takes a guest to the host's hut.
    • Fixed: with a guest driving, the host standing aboard fell through the floor (the game turns the floor off for whoever drives, assuming it is the local player in the seat). The floor now stays on.
    • To do: check the game's own way of taking the controls on a guest. The test save is too early in the story: taking control is still locked there.

    Exit: two players stand in the hut while it walks 500 m, with no jitter and no one falling through. Met (guest driving, host standing aboard, ~500 m; neither moved on the floor).

  8. Shared world objects

    doneworld

    Foraging, pickups, loot, containers and animals. The first request to the host wins, and AI runs on the host and is mirrored to guests. Everyone shares one pack (items, money, building blocks, clothes), kept in the host's save.

    • Done: deer, hares and villagers near a guest copy the host's: position, facing and what they are doing (grazing, drinking, sitting, working). A villager that stands still is sent once a second, and far away a lighter sync takes over.
    • Done: carrying hares and liftable things, in both directions. Others see the carried pose and the carrier's arms.
    • Done: town freezes. A place that took 60 ms to check every 30 s now takes 2 ms, and the scene scan no longer stalls on 12,500 objects. The 35-50 ms hitches every half minute came from garbage the scan made; most half minutes now have no frame over 50 ms.
    • Done: guests startle deer too: the host's flee checks look at the nearest player, and the deer runs from that one.

    Exit: both players grab the same mushroom at once, and it is picked once and appears in one inventory. Met (3 of 3 races: the host's grab kept it, the guest's copy was given back).

  9. Build together

    donebuilding

    Each placement travels as the game's own HouseBlockSpec. The host re-checks it, assigns the placementIndex and broadcasts; remote pieces are spawned without paying or touching undo. Whole-hut resync uses the game's own house loader.

    • Done: each player numbers new blocks in their own lane, so two players building at once never pick the same number. Two fuzz runs (200 and 300 random builds and removals from both players at once, a few a second each) ended with identical houses.

    Exit: 200 fuzzed concurrent edits leave both clients with an identical House.xml. Met.

  10. Villagers, quests, story

    in progressstory

    Effect capture on Quest, TasksTracker, ChapterState and JournalManager. Dialogue runs once, on the host; whoever starts a conversation leads it and pulls nearby players in. Quest rewards are granted to every player. FMOD events are replayed on puppets.

    Next, as core systems rather than quest by quest (from the 2026-10-27 evening playtest):

    • Quest and story sync: the host's quest and story progress goes to guests whenever it changes, and their game loads it the way it loads a save. Quest-gated things then appear for everyone (the crows in an early quest were missing for the guest).
    • Shared grants: whatever the story gives a player (skills such as raven fetch, unlocks, journal entries) is repeated for every player. The guest got the journal and the Tab inventory from Baba Jaga but not raven fetch.
    • A conversation state machine: one talk at a time with clear states and one owner, every step confirmed, and clean recovery when someone leaves or walks off. Players sometimes got stuck in each other's dialogues.
    • Then a short list of special scenes that need their own handling, found by playing (Baba Jaga's dialogue and book did not reach the guest).
    • Built in 0.3.9, checked with dev commands and waiting for a playtest: saved progress (skill and tool unlocks, tutorial steps, the collection) follows the host; story objects the quests switch on or off follow the host; conversations have a host-run state that guests check every second, a continue that can't get lost, a 45 s limit on a guest's choice, and a host far from a guest's talk stays free to walk.
    • Built in 0.3.10: a desync detector. Every 15 s the guest compares story flags, trials, saved progress, story objects and the pack with the host's, and writes anything that stays different to desync.log, so a playtest's "she couldn't see it" can be read off afterwards. It found that the tutorial's talking crows were never mirrored to guests (they now are). On a fresh local campaign the guest matched the host through the whole prologue.
    • 0.3.11, for the game's hotfix 1.0.25: the patched game crashed at start with BepInEx (a hook in its IL2CPP layer landed on the wrong function); the mod now corrects that, and the package turns off BepInEx's Unity log listener. A guest's join could drop into the new-game intro instead of the host's world; fixed. Checked locally on the new build: join, desync checks all matching, villagers and crows in place.
    • 0.3.12, conversations as one for everyone, tested together: the starter steers; the others are moved beside them and see the starter's camera, skipped typing and highlighted option, and their own buttons can't move or end it. Puppets no longer turn up in the other player's clothes.
    • 0.3.13: the desync detector now fixes what it finds on the guest (story objects on or off, trial progress) instead of only logging it. Carrying the merchant's lost wheel is shared (it had no id). A walking check over 30 s of turns put the other player's copy within 3 cm (95th percentile).

    Exit: a scripted chapter playthrough with matching progress digests at every step.

Build order

  1. Clock and weather. Done. The host sends the game's own weather snapshot (time of day, clouds, fog, rain, forecast) every 5 s and to anyone who joins; guests apply it and don't roll their own. Verified: host set to 8 pm with heavy cloud, the client followed within one snapshot.
  2. Gear on the other player. Done. Backpack, held items and the lantern copy onto the other player and follow their bones; arm layer weights are synced; footsteps play at their feet. Switching tools is verified: the lantern moves between hand and backpack hook, the pine branch between hand and backpack slot.
  3. Join by save transfer. Done. The host sends its save when someone joins; the guest loads it into a sandbox and never saves. Verified with a client that had no save at all. When the host travels to a new map, guests follow: the host's arrival save is sent and loaded where they stand, and each guest keeps their own pack. Verified with a real trip.
  4. Shared pack and pickups. Done. Since 0.3.7 everyone shares one pack, the host's own: items, money, building blocks and plans, clothes. Changes go out as small deltas the host applies and relays, and a full copy every few seconds corrects any drift; tested with three players, a late join and both sides changing it at once. Anything picked up from the world disappears for everyone and stays gone in the host's save. Verified both ways, and across a restart. Trees, pots and chest contents are shared too: what anyone puts in a chest or oven is there for everyone and survives the host's save. When two players grab the same item in the same instant, the host's order decides and the other gives their copy back.
  5. Hut. Working. The host's hut is mirrored on guests (pose and walk animation), a guest calling the hut asks the host, and riders stay put on the moving floor on both screens. The feather colour is shared. The ground flattening and props hiding when the hut sits now happen on guests too. A guest at the controls steers it for everyone, and backport lands guests at it.
  6. Building. Done. House blocks and furniture placed, removed or changed by anyone appear for everyone; the builder pays from their own pack. The house is identical on both screens and a guest's block survives the host's save. Blueprint sites are shared. Two blocks placed in the same instant used to leave the houses different; now the host moves the later block to a free slot and both stay identical.
  7. Hut stations and gardens. Done. Cauldron and oven queues, the mill, the candle maker, plants, ivy and on/off pieces like lamps are shared through the game's own save entries. Verified with plant growth both ways.
  8. Story. Working. Since 0.3.8 whoever starts a conversation leads it, and it runs once, on the host. A guest talking to a villager, starting a story scene or handing something in (berries to the wood creatures) has the host's copy do it. Players near the speaker get the full conversation on their own screen, dialogue camera included. The leader picks the options and anyone can move a line on. Players further away get subtitles. Quest rewards land in the shared pack, and loot bags in trees and wells open for anyone. The story's flags, trial progress (current trial, ticked tasks, finished quest steps) and the state of every place on the map (91 on the test map) follow the host. Guests can't move the trial on alone. Villagers and animals follow the host's: same behaviour, same destination, same spot within about a metre. Small drift is walked off. Deer flee from guests as well as the host.
  9. Frame cost. Done. All this syncing first caused hitches of up to half a second, because searching the game's scene is slow. Lookups are now cached and the checks spread across frames, the scan reuses its lists instead of making garbage, and places and hut pieces far from everyone are checked less often.
  10. First new-campaign playtest (2026-10-27). Tutorial and first area with two players. Since fixed: the lantern's light on the other player, the first line after a pick, pickups in tight piles, loot bags for guests, and the raven spell is now visible to the other player. Joining waits until the host is through the fog. Conversations (0.3.8): whoever starts one pulls everyone in, with the dialogue camera, and the berry hand-in works for guests. Needs a playtest.
  11. Second two-PC playtest (2026-10-27 evening). A new campaign on the day-one patch (build 26225334); the mod was rebuilt for it. Conversations are much better but not solid yet. Quest progress and the story's grants don't fully reach the guest. Next: quest and story sync, shared grants, and a conversation state machine (see Villagers, quests, story). All three built in 0.3.9; needs the next playtest.
  12. Steam lobbies. Built. Invites, Join Game and Steam-relayed play, plus reconnecting after a host restart. Ready for the first two-PC test; until then, direct IP works as before.

Decisions (made 2026-10-26, updated 2026-10-27)

1. Inventory: one shared pack (changed 2026-10-27). Everything is shared: items, money, building blocks and plans, clothes. It lives in the host's save, which suits dropping in and out. Collect quests count the shared pack, so both players' mushrooms add up.
2. Dialogue: whoever starts it leads. Changed 2026-10-27. Any player can start a conversation; it runs once, on the host, and pulls in everyone nearby (same lines, dialogue camera). The player who started it picks the options; the others see them.
3. Player cap: designed for 4, tested with 2.
4. Guest progress: none. Guests never touch their own saves; everything they do lives in the host's world.

Risks

1.0 launched today. Early patches will move hooks. Every hook lives in one table checked at startup, and the mod disables itself cleanly when the build ID doesn't match.
Facepunch stripping. Cleared for lobbies. The lobby methods work. Game traffic doesn't depend on Facepunch at all: it calls the game's own steam_api64.dll directly.
New maps. Solved without regenerating on guests: when the host travels, its arrival save is sent and loaded on every guest. Loading a save re-runs the map jump with the saved generation, which the mod now tells apart from real travel.
Steam Cloud. A guest's sandboxed save slot must never sync to the cloud, or it overwrites their real saves.
One Steam account per PC. Local multi-instance tests run over LiteNetLib with a mocked Steam layer. Real Steam networking needs a second account or PC.

About coop-anything

MCP server: skip it. It's a read-only Python server that mostly serves the repo's markdown. The only parts that add anything are game_identity, detect_engine and validate_entry, and the identity work is already done. A local clone does the same job.

Keep: the playbook pages on effect capture, actor ownership and fuzzing, the Steam networking gotchas, and the Python tools that don't depend on the engine (gamepool, gameslot, chaos relay, bot scenarios, flight-recorder analyzer).

Do it our own way:

  • C++ tools: bridge, ownership, fuzz and fakeworld are C++. We port the ideas to C#, and the Python clients keep working.
  • hotreload: it doesn't apply, because BepInEx IL2CPP can't unload assemblies. A fast build-deploy-restart loop from the Big Walk skill replaces it.
  • Spacewar 480: it's irrelevant, because Reka already initializes Steam under its real app ID.
  • Pull requests: skip the per-phase ones. Contribute once something works.
